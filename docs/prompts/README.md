# Промпты для роликов-демонстраций

Один файл на упражнение: `NN-<visual>.md`, где `<visual>` — ключ из `data.js`. Всего 24 упражнения.
Состояние на 05.11.2026: **22 ролика готовы и подключены**, 2 показываются схемой или картинкой (`chin`, `stretch`, см. таблицу).

## Как делали (два способа, оба на Grok Imagine Video)

| Способ | Что умеет | Ограничения |
|--------|-----------|-------------|
| **Веб** (MCP `grok-imagine-xai`, драйвер «web», подписка пользователя) | image-to-video: один стартовый кадр; **с 05.11.2026 и референсы** (`image_paths` из 2+ картинок, в промпте `@Image 1`, `@Image 2`) | длительность 6 / 10 / 15 с; форматы 3:2, 2:3, 1:1, 9:16, 16:9 (4:3 нет); с одним кадром формат берётся из него, с референсами задаётся `aspect_ratio`; без `last_frame`; картинки только по тексту, image-to-image нет |
| **API** (MCP `grok-imagine`, платный ключ xAI) | то же + `reference_images` (персонаж по листу), `last_frame`, любые длительности, 4:3 | **платный, стоимость не отдаёт**; после ролика 4 «walk» и «bridge» кредиты закончились |

Используйте веб-способ. API — только по явной команде пользователя, с названием стоимости.

### Правила веб-способа (проверено)

1. **Стартовый кадр** — готовый кадр мальчика из репозитория, достроенный фоном до 3:2 (1350×900):
   `ffmpeg -i boy-front.png -vf "pad=1350:900:315:0,fillborders=left=315:right=315:mode=smear" boy-front-32.png`
   Есть: `assets/art/boy-front-32.png`, `boy-side-right-32.png`, `boy-side-left-32.png`, `boy-back-32.png`, `mat-lying-32.png` (лёжа на коврике, кадр из ролика «bridge»), `boy-front-32h.png` (фигура 88% высоты, запас над головой).
2. **Запас над головой.** Если в упражнении тело вытягивается или руки идут вверх, использовать кадр `…-32h.png`: на плотном кадре голова уходит за край.
3. **Позы с реквизитом (стул, стена сбоку, четвереньки) — режим референсов, без стартового кадра.** `image_paths` = [`assets/art/sheet-character.png`, `boy-side-right.png` или `boy-front.png`], `aspect_ratio` 3:2, 720p; в промпте описать внешность и реквизит, ссылаться на `@Image 1` / `@Image 2`. Персонаж держится хорошо (10 роликов от 05.11.2026). Петля хуже, чем с кадром: проверять SSIM, при нужде обрезать ролик на кадре, ближайшем к первому (так сделан `bird`).
   **Сбой драйвера:** Grok пишет прогресс «Генерация NN%», а драйвер знает только «Создаётся/Generating/Creating» (`PROGRESS_WORDS` в `grok_page.py` репозитория Content_factory). Через 45 с он ставит задаче `failed`, хотя ролик догенерируется. Готовые ролики забирать `grok_library_list` → `grok_library_download` (лимит не тратят).
4. Формулировать движение **запретами**: «arms hang straight down and never move», «head never tilts», «hips never lift». Без них модель додумывает (разводит руки, делает мост вместо дыхания).
5. В конец промпта дописывать «The video ends in exactly the same pose as the first frame» (петля). Контроль: SSIM первого и последнего кадра ≥ 0,9.
6. Точные промпты принятых роликов: `docs/prompts/WEB_PROMPTS.md`.

## Проверка и сжатие

1. Контактный лист: `ffmpeg -i clip.mp4 -vf "fps=2.5,scale=300:-1,tile=5x3" -frames:v 1 sheet.png`.
2. Петля: первый и последний кадр, `ffmpeg -i first.png -i last.png -lavfi ssim -f null -`.
3. Сжатие: `tools/encode-video.sh clip.mp4 <visual>` → `assets/video/<visual>.mp4` (H.264) и `.webm` (VP9), ширина 960, без звука. После — запись в `POSE_VIDEOS` (`data.js`) и в список роликов в `sw.js`, поднять `CACHE_VERSION`.
